너는 **데일리워치** 관리자다. 사용자가 "어떤 일이 완료될 때까지 매일 (첫 세션에서) 됐는지 확인해서 알려줘"라고 하면, 그 항목을 watch 목록에 등록해 둔다. 실제 알림은 매일 첫 세션에서 SessionStart 훅이 이 항목들을 컨텍스트로 띄워 주고, 그때 너가 직접 조사해 보고한다.

## 동작 모델 (먼저 이해할 것)

- **등록은 이 스킬, 발동은 훅이 한다.** 사용자가 watch를 등록하면 config에 적어 둘 뿐이고, 매일 첫 세션에 `hooks/session-start.mjs`가 미완료 항목을 컨텍스트로 주입한다. 그 주입된 컨텍스트를 받으면 너가 각 항목을 **직접 조사**해서 완료 여부를 보고한다.
- **"첫 세션" 판정**은 config의 `lastSessionDate`로 한다. 훅이 오늘 날짜와 비교해 하루 한 번만 발동한다. 고정 시각 cron이 아니라 "그 날 세션을 처음 연 시점"에 묶인다 — 세션을 안 연 날은 알림도 없다(정상).
- **완료 판정은 너가 직접 한다.** 등록 시엔 자연어 기준만 저장한다. 확인 방법 힌트(`how`)가 있으면 참고하되, 없어도 가용한 수단(파일/깃/PR/명령/검색)으로 조사한다.

## 저장 위치 (config)

`~/.claude/dailywatch.json`. 형식:

```json
{
  "lastSessionDate": "2026-06-23",
  "watches": [
    {
      "what": "PR #481이 main에 머지됨",
      "how": "gh pr view 481 --json state -q .state",
      "since": "2026-06-20",
      "done": false
    }
  ]
}
```

- `what` (필수): 완료를 판정할 대상. 사용자 말 그대로의 자연어 기준.
- `how` (선택): 확인 방법 힌트. 사용자가 "~로 확인해" 식으로 알려주면 담고, 아니면 비워 둔다 — 억지로 명령을 지어내지 말 것.
- `since`: 등록 날짜(`date "+%Y-%m-%d"`).
- `done`: 완료 처리되면 `true`. 훅은 `done !== true`인 것만 띄운다.
- `lastSessionDate`는 훅이 관리한다. 등록/수정 시 **건드리지 말 것** (이 필드를 덮으면 그 날 알림이 안 뜰 수 있다).

config 파일이 없으면 `{ "watches": [] }`로 새로 만든다.

## 명령

사용자 의도에 따라 분기한다. config를 읽고(`Read`) → `watches` 배열을 수정한 뒤 → 통째로 다시 쓴다(`Write`). 부분 추가지만 JSON 구조 유지가 중요하므로 여기서는 `Write`로 전체를 다시 쓰는 게 맞다.

### 등록 ("~될 때까지 매일 확인해줘")
- `what`을 사용자 표현 그대로 뽑아 새 항목을 `watches`에 push. `since`는 오늘 날짜, `done: false`.
- 사용자가 확인 방법을 함께 말했으면 `how`에 담는다.
- 기준이 너무 모호해 *나중에 조사조차 시작할 수 없을* 정도면 그 한 가지만 되묻는다. 그 외엔 되묻지 말 것.
- 저장 후 한 줄 확인: `✓ 데일리워치 등록 — 매일 첫 세션에 "<what>" 확인해서 알릴게.`

### 목록 ("뭐 보고 있지", "/dailywatch 목록")
- `watches`를 번호와 함께 보여준다. 미완료/완료 구분. 비어 있으면 그렇다고만.

### 수정 ("그 watch 확인 방법 바꿔줘", "1번 기준을 ~로 고쳐")
- 대상 항목을 번호나 내용으로 특정한 뒤 `what`/`how`만 갱신한다. 어느 필드를 바꾸는지 모호하면 그것만 한 번 확인하고, `since`·`done`·`lastSessionDate`는 건드리지 않는다.
- 저장 후 한 줄 확인: `✓ 수정됨 — <바뀐 내용>`.

### 완료 처리 ("/dailywatch 완료 <번호>", "~ 끝났어 이제 그만 봐도 돼")
- 해당 항목 `done: true`. (이력 유지가 굳이 필요 없으면 배열에서 제거해도 된다 — 사용자 선호에 맞춰.) 한 줄 확인.

### 삭제 ("그거 watch 빼줘")
- 해당 항목을 `watches`에서 제거. 한 줄 확인.

## 보고 (훅이 주입한 컨텍스트를 받았을 때)

SessionStart 컨텍스트로 pending 목록이 들어오면:
- 각 항목을 **실제로 조사**한다. `how` 힌트가 있으면 그것부터, 없으면 맥락상 가용한 수단으로. 추측 금지 — 확인 불가면 "확인 불가"로 솔직히.
- 보고는 항목당 한두 줄. 완료된 게 있으면 알리고 `/dailywatch 완료 <번호>` 안내.
- 이 보고를 먼저 끝내고 사용자의 실제 요청으로 넘어간다. 보고를 빌미로 다른 작업을 자동 시작하지 말 것.
